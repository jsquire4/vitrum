# Changelog

All notable changes to this monorepo will be documented here.

The format is based on [Keep a Changelog](https://keepachangelog.com/en/1.1.0/), and this project adheres to [Semantic Versioning](https://semver.org/spec/v2.0.0.html) **once** packages leave **pre-alpha** (see root `README.md`). Until then, versions may remain `0.0.0` and breaking API moves are noted here without minor/major bumps.

### Added

- **`@vitrum/walkaround-hybrid` DDGI atlas border fill pass** (sweep 2026-05-11, Item 3): new `ddgi/wgsl/probeUpdateBorder.wgsl.ts` implements `probeUpdateBorderIrradiance` and `probeUpdateBorderVisibility` compute kernels that populate the 1-pixel border ring of every probe's octahedral atlas cell per Majercik 2019 §3.2 / Cigolle 2014 §A.1. Fixes systematic darkening at octahedral seams where bilinear sampling previously read zero-initialized border pixels. Implementation: after each `probeUpdateBlend` dispatch, the host copies the blend-output atlas into a per-atlas scratch texture (`irrScratchTex` / `visScratchTex`) to sidestep the WebGPU restriction against simultaneous `texture_2d` read + `texture_storage_2d` write on the same texture, then dispatches the border pass reading from scratch and writing to the write-side atlas. Two new pass-layout slots (`ddgi-border-irr`, `ddgi-border-vis`) appended after `indirect-combine`; `MAX_PASS_COUNT` raised from 26 to 28.

### Changed

- **`@vitrum/pt-webgpu` BVH encoding canonicalized to relative offsets** (Foundations #26 / D10): `buildCpuBvh` now stores `rightChild − nodeIndex` (relative) instead of the absolute right-child node index. The WGSL traversal in `pathTraceBruteforce.wgsl.ts` updated to match (`let rightChild = nodeIdx + node.rightChildOrTriOffset`). Both sides updated atomically — a partial update would silently produce wrong pixels. Encoding now matches `shared-bvh/normalizeBvhInteriorOffsets` and walkaround-hybrid's `common.wgsl` convention. Dev/test mode: post-build invariant check (`1 ≤ offset < totalNodes` per interior node) added inline. `buildCpuBvh.test.ts` extended with relative-offset assertion.
- **`@vitrum/shared-bvh` index-buffer stride contracts formalised** (Foundations #27): exported `BvhIndexStride = 3 | 4` type; added `bvhIndexStride: 3` field to `SceneBVHCommonResult` (`buildSceneBVH` always returns stride 3 — callers that need stride 4 must post-process). `validateBvhEncoding(nodeBytes, totalNodes)` helper exported for cross-package invariant enforcement. pt-webgpu `uploadSceneBuffers.ts` adds an upload-time assertion (`indices.byteLength % 16 === 0`) and documents the stride-4 zero-fill contract on `PackedSceneData.indices`.
- **`@vitrum/pt-webgpu` BVH builder replaced with binned SAH** (Foundations #31 / D10): `buildCpuBvh.ts` median-split replaced with Wald 2007 binned Surface Area Heuristic (K=16 bins per axis). All three axes are evaluated; the cheapest split plane is chosen. If no split is cheaper than a leaf, a leaf is created early (median-split never exploits this). Relative right-child offsets preserved throughout. Hit results are identical to median-split for the same geometry (different BVH topology, same intersections).

### Fixed

- **pt-webgpu VNDF GGX sampling** (Foundations #14): replaced `glossyReflectionSample`'s ad-hoc `mix(reflectDir, cosineHemiSample, roughness²)` lerp with Heitz 2018 "Sampling the GGX Distribution of Visible Normals" JCGT 7(4) Algorithm 1. The lerp distribution was incompatible with the GGX half-vector PDF already used in `brdfDirectionalPdf`, causing a biased MC estimator at mid roughness (systematic energy loss on glossy surfaces at roughness 0.3–0.7). The new `sampleGgxVndfTangent` helper transforms `wo` to the unit-roughness configuration, samples a visible half-vector via Frisvad ONB and concentric disc remapping, then unstretch-normalises back. Signature of `glossyReflectionSample` updated to accept `(rng, wo, n, t, b, roughness)` (caller builds ONB via `buildOnb`). (`@vitrum/pt-webgpu`, sweep-2026-05-11 Item 14)
- **pt-webgpu dielectric Fresnel branch** (Foundations #16): replaced the heuristic `transProb = transmission * (1 - metallic)` random-walk split with an exact physical Fresnel-weighted partition per PBR4e §9.3 `FrDielectric()`. New `frDielectric(cosTheta_i, eta)` helper computes unpolarised Fresnel reflectance including TIR (returns 1.0 at and above the critical angle). For transmissive, non-metallic surfaces, the Monte Carlo estimator now selects specular-reflect with probability R = frDielectric(|N·wo|, ior) and refract with probability (1−R), dividing throughput by the chosen probability. TIR is automatically handled (R=1 means refract is never sampled). Thin-film transmit tint still applied to the refraction branch. Non-transmissive surfaces keep the existing heuristic diffuse/specular partition. (`@vitrum/pt-webgpu`, sweep-2026-05-11 Item 16 / D11 analogue)
- **pt-webgpu BSDF→light MIS single-light bug** (Foundations #15): `intersectRectAreaLightRay` and `intersectMeshAreaLightRay` previously hardcoded `[0]` light-buffer indexing, so BSDF-sampled direction could only connect to the first rect-area or mesh-area light. Generalised both to accept a light index `li: u32` (stride `li * 4u`). `bsdfAreaLightConnectionContribution` now loops all `params.rectAreaLightCount` and `params.meshAreaLightCount` lights, keeping the minimum-distance unoccluded hit — sum MIS over all lights is unbiased and costs O(N_lights) extra intersection tests per bounce (typical scenes ≤ 8 lights, D9 decision). (`@vitrum/pt-webgpu`, sweep-2026-05-11 Item 15)

- **equiAngular** (Engines #10): PDF now computed at the clamped `t` value (was unclamped, causing PDF/sample mismatch in degenerate geometry); guard added for near-zero `thetaRange` (light direction nearly perpendicular to the ray) returning `{ t: 0, pdf: 0 }` to avoid downstream division by zero. (`@vitrum/shared-samplers`)
- **transformNormal** (Foundations #17): added `transformNormal(m, v)` — inverse-transpose (cofactor matrix) normal transform — to `pt-webgpu/math/mat4.ts`; fixes shading normals on instances under non-uniform scale where using `transformDirection` (M·n) incorrectly distorts normals. Call site in `uploadSceneBuffers.ts` updated. (`@vitrum/pt-webgpu`)
- **halfFloat encoder** (Foundations #33-H / F9): finite f32 inputs > 65504 now saturate to ±Inf as IEEE 754 specifies, not to a quiet-NaN bit pattern. (`@vitrum/shared-denoisers`)
- **`@vitrum/pt-webgpu`**: removed arbitrary 32-unit Beer-Lambert clamp (`min(hit.dist, 32.0)` → `hit.dist`); UBO-plumbed `triIntersectEpsilon` replacing one padding slot in `FrameParams` (default 1e-5, metre-scale, host-overridable); added `safeInvDir` IEEE-safe AABB-slab helper in `common.wgsl.ts` and replaced two raw `vec3f(1.0) / ray.direction` divisions in `intersectAabb` / `intersectAabbDetailed` (Williams 2005 §4 NaN fix for axis-aligned rays coincident with AABB face planes). (Items 18, 28, 36 / D12 — sweep 2026-05-11.)
- **ReSTIR-DI p̂ consistency** (Engines #5): unify the emitter geometry term across RIS, temporal, and spatial reuse passes. Per Bitterli 2020 §4.3, p̂ must be identical across all reuse steps to keep the WRS estimator's W_q ratio computation correct. Restores the firefly suppression that the RIS-only `emitterDist2Floor` clamp was meant to provide.
- **Atrous-variance depth channel** (Engines #7 / D2): shader now reads linear depth from `.x` matching the host upload (previously read from `.w` which was zero-initialized; depth-aware filtering silently no-op'd on every real call).
- **walkaround-hybrid ordered BVH traversal** (Foundations #30): `bvhIntersectAny` and `bvhIntersectFirstHit` in `common.wgsl.ts` now use split-axis ordered traversal (Wald 2007 / PBR4e §7.3.3). Low 2 bits of `splitAxisOrTriCount` give the split axis; ray direction sign on that axis determines near/far child order; far child is pushed first so near child is popped and tested first. Expected 30–50% fewer node tests for first-hit queries on coherent rays; smaller but positive gain for any-hit (shadow) queries. Hit results are identical to unordered traversal — only traversal efficiency changes. (`@vitrum/walkaround-hybrid`, sweep-2026-05-11 Item 30)
- **M7 DDGI Coherent Physical Model** (`@vitrum/walkaround-hybrid`, sweep-2026-05-11 Items 2, 4, 6, 20 + band-aid removal): Five changes that jointly redefine the DDGI energy contract end-to-end. Must be read as a single atomic milestone:
  1. **Item 6 — Unfreeze `randomRotation` (Shoemake SO(3))**: `probeUpdatePass.ts` replaces the all-zeros per-frame rotation with a deterministic Halton-{2,3,5} quasi-random SO(3) sequence (Shoemake 1992). Decorrelates probe ray samples across frames so the EMA temporal hysteresis accumulates an effectively larger ray budget.
  2. **Item 20 / D5 — Paper Lambertian cosine blend kernel**: `probeUpdateBlend.wgsl.ts` irradiance blend kernel changes `pow(w, 8.0)` → `w` (Majercik 2019 §3 Algorithm 1). Visibility blend changes `pow(w, 50.0)` → `pow(w, 2.0)`. Atlas now accumulates true irradiance E instead of a directionally-filtered radiance approximation.
  3. **Item 2 — Remove `* albedo / PI` from producer**: `probeUpdateRays.wgsl.ts` stores raw incoming radiance L_i. Combined with the cosine blend kernel (Item 20), the atlas holds true irradiance E. The receiver applies `(albedo/π) · E` — eliminating the `albedo²/π²` double-multiply that required the commit `3fb63e3` band-aid gain reduction.
  4. **Item 4 / D1 — Fix RC GI BRDF injection**: `giReceiver.ts` changes `nm.emissiveNode = giNode` → `nm.emissiveNode = mul(giNode, mul(materialColor, PI_INV))`. GI signal is now correctly interpreted as irradiance E; the receiver applies the Lambertian BRDF before injecting via `emissiveNode`. `three/tsl` imports extended with `mul`, `uniform`, `materialColor`.
  5. **Band-aid removal + comment update**: `applyDDGIShading.ts` receiver comment updated to document the M7 energy contract (atlas holds irradiance E; consumer applies `albedo/π`).
  - Visual verification pending GPU run. If results look incorrect, investigate the math (e.g., check cosine basis implementation in blend) — do NOT add band-aid gain factors. Reference equation: `L_o_indirect = (albedo/π) · E_ddgi` (Majercik 2019 §3).
