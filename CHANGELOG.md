### Added

- **pt-webgpu lite + full trace tiers (2026-05-26):** lite layout for SwiftShader-class adapters (≤10 buffers / ≤4 textures); full layout splits path-trace bindings across three groups (≤10 buffers each) so Chrome-class GPUs (16/8) get TLAS, HDRI, area lights, motion/variance aux, and caustics without the old single-group 23-buffer requirement.
- **Hybrid TLAS production path (2026-05-26):** `InstancedMesh` through `@vitrum/three-bindings`, uuid-aware `updatePrimitive` / ReSTIR material resolution, `hybridTlasTraverse` tests, and Windows GPU PR-hybrid bench runner (`run-gpu-host-windows.mjs`).
- **WG-0 baseline (2026-05-26):** committed `tools/reference-renders/baseline/ptwgpu-parity-material-fields.png`; strict hash verification via `VITRUM_STRICT_GAP_CLOSURE=1` on hardware (`npm run benchmark:gpu-windows -- run-gap-closure-verification.mjs …`).

- **Wave-4 reliability gate runners (2026-05-26):**
  - `@vitrum/benchmark-runner` gained `run-lifecycle-soak.mjs` for repeated lifecycle churn checks (navigation/quality/size permutations with telemetry-progress assertions and optional dev-server auto-start).
  - Added `run-wave4-hardening.mjs` orchestration gate (`hardening:wave4`) combining mechanical checks, strict lifecycle soak, and optional quality-mode smoke pass into a single report artifact under `tools/benchmark-runner/results/wave4/`.
  - Added benchmark-runner workspace validation scripts (`npm run typecheck --workspace @vitrum/benchmark-runner`, `npm test --workspace @vitrum/benchmark-runner`) using syntax checks across all local runner entrypoints.

- **Coherence + contract truthfulness sweep (2026-05-25):**
  - `EngineCapabilities` gained explicit capability matrix fields: `supportedPrimitiveKinds`, `supportedEnvironmentKinds`, `incrementalPatchSupport`, `presentationMode`, and `experimentalFeatures`.
  - New `@vitrum/stained-glass-extensions` package extracted stained-glass-specific wire contracts (`SURFACE_TEXTURE_ID`, `VITRUM_USER_DATA_KEYS`, came UBO packer).
  - Area-light PDF robustness guards landed in fork shader sampling (`light_sampling_functions.glsl.js`) with smoke-check coverage to prevent NaN/Inf regressions.
  - SVGF-real object-ID fallback switched to conservative history rejection (`currObjId=0`, `prevObjId=1`) until true object-ID buffers are wired.

### Changed

- Benchmark-runner env parsing now fail-fast for invalid numeric configuration values (quality-mode bench + lifecycle soak), preventing silent NaN-driven false positives.
- Project maturity wording is normalized from "pre-alpha/prototype" to "experimental backend" across active architecture docs (`README.md`, `AGENTS.md`, `CLAUDE.md`, `plan/library-architecture.md`).

- `FrameInput` swap-chain handles are now strictly branded backend textures; host callsites must brand `swapChainView` / `swapChainFormat` using `asBackendTexture` and `asBackendTextureFormat`.
- `@vitrum/pt-webgl` and `@vitrum/pt-webgpu` now expose patch methods through the engine surface and truthfully report patch granularity via `incrementalPatchSupport`.
- `@vitrum/walkaround-hybrid` root export surface is trimmed to engine-facing API; broad internal shader/PPG/RC exports were removed from the package root.

- **C2 — TLAS module in `@vitrum/shared-bvh`** (`5cf642b`, 2026-05-19): top-level acceleration structure builder, refit, and CPU reference traversal. `buildTlas(instances, opts?)` runs binned SAH (K=16) over instance world AABBs and emits the same 32-byte node layout as the BLAS so `bvhIntersect.wgsl` primitives can be reused with only the leaf-payload decode varying. `refitTlas(data, newAabbs)` is the O(nodes) bottom-up bounds refresh used when instance transforms change but topology is unchanged. `tlasIntersect(...)` is the CPU reference oracle for tests (returns candidates; with `maxLeafInstances: 1` the candidate set equals the precise hit set). Signed-int32 leaf-flag check (`0xFFFF0000 &` is `-65536` in JS unless routed through `>>> 0`) caught and fixed in the same pass — 17 tests pin build / refit / traversal / candidate-semantics / error paths. Pipeline wiring (WGSL traverse-into-BLAS + bvh-common adapter to emit per-mesh BLAS roots) is the multi-week follow-up; this module is the load-bearing foundation that lets that work proceed without rebuilding from scratch.

- **C1 — SkinnedMesh end-to-end (contract + CPU solver + morph targets)** (`7d0f4d7` + `f3a91ce`, 2026-05-19): `SkinnedMeshPrimitive` added to `@vitrum/core`'s `ScenePrimitive` discriminated union; `sceneFromThreeJS` now converts `THREE.SkinnedMesh` instead of throwing. Adapter extracts skinIndex/skinWeight, flattens `skeleton.bones[i].matrixWorld` + `skeleton.boneInverses[i]` into single Float32Arrays, captures rest-pose positions/normals/uvs/tangents/indices, and pulls morph attributes (auto-converts absolute morphs to deltas per `morphTargetsRelative === false`). `solveSkin(prim)` is the per-frame linear-blend skinning solver — applies morph deltas BEFORE bone transform per glTF 2.0; precomputes `combined = bones · boneInverses` once per call (boneCount × mat4mul) instead of per-vertex×bone. Normals use the upper 3x3 of the skin matrix (rigid-bone correct; inverse-transpose for scaled bones deferred). `vitrumSceneToThree` pre-solves at scene-build time and emits a static THREE.Mesh; per-frame pose updates flow through `engine.updatePrimitive(id, { positions, normals })` which already exists. Downstream consumers updated: `@vitrum/engine` `sceneAABB` uses rest-pose AABB for skinned-mesh; `@vitrum/walkaround-hybrid` `_coreSceneSuppliesMeshes` includes skinned-mesh; `@vitrum/pt-webgpu` `summarizeScene` exposes `skinnedMeshPrimitiveCount`. 19 tests pin conversion + solver math (identity / translation / rotZ-90 / two-bone-blend / in-place writes / 4 morph cases / shape errors).

- **T3.A — `@vitrum/engine` package + unified `createEngine()` factory** (47e22d8): new thin-facade package exposing the five-line drop-in `const engine = await createEngine({ canvas, scene, camera });`. Probes WebGPU vs WebGL2 via `@vitrum/core`'s `detectGpu`, picks `walkaround-hybrid` (WebGPU realtime GI) or `pt-webgl` (WebGL2 path tracing) per a `prefer: 'auto' | 'realtime' | 'quality'` hint (`'auto'` uses walkaround for scenes <500k tris on WebGPU, pt-webgl otherwise). Accepts either `THREE.Scene` or `@vitrum/core` `Scene`; auto-converts THREE via `@vitrum/three-bindings`. Computes scene AABB diagonal `D` and derives scale-sensitive defaults (`cameraMoveResetThresholdSq = (D·1e-3)²`, `emitterDist2Floor = (D·1e-4)²`, `triIntersectEpsilon = D·1e-6`, `temporalAccumAlpha = 0.01`) so Cornell-tuned numerics no longer leak into jewellery- or city-block-scale scenes. Owns the device handle it creates; idempotent dispose via a thin proxy. 15 unit tests across `pickBackend`, `deriveScaleDefaults`, `computeSceneAABB`. Plan deviation: factory lives in a new `@vitrum/engine` package rather than `@vitrum/core` because the factory has to construct backend engines and `@vitrum/core` has no backend deps; placing it in core would force circular deps or brittle dynamic imports.

- **T3.E — `engine.onFrame()` / `engine.onProgress()` telemetry hooks** (`@vitrum/core` + `@vitrum/walkaround-hybrid` + `@vitrum/pt-webgl`, 16adbe1): two optional methods on the `Engine` contract — `onFrame?(cb: (stats: FrameStats) => void): () => void` and `onProgress?(cb: (progress: ProgressStats) => void): () => void`. Both throw-safe (subscriber throws are swallowed so the render loop stays alive). `walkaround-hybrid` fires `onFrame` at end of each successful `renderFrame()` with `frameTimeMs`, `spp=1`, and per-pass `gpuTimeMs` pulled from timestamp queries when available; `onProgress` intentionally absent. `pt-webgl` emits `{frameTimeMs, spp}` and `{kind: 'pt-spp', current, target, fraction}` per frame. `@vitrum/engine` `wrapWithIdempotentDispose` proxy conditionally forwards both methods via the exactOptionalPropertyTypes-friendly spread pattern; post-dispose subscribe returns a no-op teardown. 6 tests in `__tests__/telemetryProxy.test.ts`.

- **T3.D — `loadGltfScene()` loader pipeline** (`@vitrum/three-bindings`, e060af7): wraps three.js's `GLTFLoader` so a host can hand vitrum a URL / Blob / File / ArrayBuffer and get back a vitrum `Scene` plus the first embedded camera. - **Barycentric Gram-determinant divide-by-zero floor in surfaceTextures shadow-ray path** (`@vitrum/walkaround-hybrid`, `fbb8bab`, 2026-05-19): the recomputed-from-hit-position barycentric calculation at `surfaceTextures.wgsl.ts:223` used `denom = d00 * d11 - d01 * d01` unfloored. - **`safeInvDir` WGSL false-positive for exact-zero direction components** (`@vitrum/shared-bvh` `3327e8c` + `@vitrum/pt-webgpu` `2740d92`, 2026-05-19): two duplicate WGSL `safeInvDir` helpers (shared-bvh's `bvhIntersect.wgsl.ts:119` + pt-webgpu's `common.wgsl.ts:64`) both used `sign(d.x) * 1e30` for near-zero directions. WGSL `sign(0) == 0` — so an exact-zero direction yielded inv-component `0`, collapsing the X slab's t0/t1 contribution to 0 regardless of origin position. Net effect: slab tests for axis-aligned rays whose origin sat OUTSIDE the AABB on the parallel axis gave false positives (tNear=tFar=0, tFar≥0), and traversal would descend the bogus node and waste cycles on ray-triangle tests for a ray that geometrically misses. Rare in PT (jittered directions are almost never exactly axis-aligned) but probe-ray paths in DDGI / RC using Halton / Hammersley sequences can hit it.
